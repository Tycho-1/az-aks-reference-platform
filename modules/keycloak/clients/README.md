# Keycloak client module

An OpenID Connect client in a Keycloak realm, configured along the lines of the
[OAuth 2.0 Security Best Current Practice](https://datatracker.ietf.org/doc/html/rfc9700) and
OAuth 2.1: authorization code flow with PKCE, no implicit or password grant, and tokens limited to
the roles the client needs.

## What you get by default

| Area | Default |
|------|---------|
| Flows | Authorization code only. Implicit flow always off; password grant and client credentials off unless enabled |
| PKCE | Required (`S256`) on the authorization code flow, for every access type |
| Redirect URIs | HTTPS only (plus `http://localhost` / `http://127.0.0.1` for development); a bare `*` is rejected |
| CORS | `+`: only the origins of the redirect URIs; `*` is rejected |
| Token scope | `full_scope_allowed = false`: tokens only contain roles mapped through client scopes |
| Secret | Generated by Keycloak for CONFIDENTIAL clients unless you pass one |

The access type is a required input, because the choice depends on the application:

| Access type | Use for |
|-------------|---------|
| `CONFIDENTIAL` | Server-side apps that can keep a secret. Prefer `client_authenticator_type = "client-jwt"` to avoid a shared secret |
| `PUBLIC` | Single-page and native apps. PKCE protects the code exchange |
| `BEARER-ONLY` | APIs that only validate access tokens. All flows are disabled |

## Usage

```hcl
module "web_client" {
  source = "../../modules/keycloak/clients"

  realm_id            = keycloak_realm.this.id
  client_id           = "sample-web"
  name                = "Sample web app"
  access_type         = "CONFIDENTIAL"
  root_url            = "https://app.example.com"
  valid_redirect_uris = ["https://app.example.com/oauth2/callback"]
}

module "worker_client" {
  source = "../../modules/keycloak/clients"

  realm_id                 = keycloak_realm.this.id
  client_id                = "sample-worker"
  access_type              = "CONFIDENTIAL"
  standard_flow_enabled    = false
  service_accounts_enabled = true # client credentials grant
}
```

Store the `client_secret` output in Key Vault (for example with `azurerm_key_vault_secret`) and
read it in the application through the Secrets Store CSI driver or workload identity.

## Notes

- **`full_scope_allowed = false`** can remove roles an application used to receive. Map the roles
  the client needs with a client scope or a scope mapping, or set the input to `true` explicitly.
- **Outputs.** `id` is Keycloak's internal UUID, which other resources (roles, protocol mappers)
  reference; `client_id` is the identifier used in OAuth requests.
- **Upgrading.** The resource address changed from `keycloak_openid_client.client` to
  `keycloak_openid_client.this`; a `moved` block migrates existing state. Inputs were renamed:
  `realm` is now `realm_id`, `client_name` is now `name`, and `redirect_url` is now
  `valid_redirect_uris`.

## Inputs

| Name | Description | Type | Default | Required |
|------|-------------|------|---------|:--------:|
| access\_type | CONFIDENTIAL for server-side apps that can keep a secret, PUBLIC for browser and native apps (PKCE only), BEARER-ONLY for APIs that only validate tokens. | `string` | n/a | yes |
| admin\_url | URL Keycloak calls for back-channel admin requests (e.g. logout). | `string` | `null` | no |
| client\_authenticator\_type | How a CONFIDENTIAL client authenticates. `client-jwt` (signed JWT, no shared secret) is stronger than `client-secret`. | `string` | `"client-secret"` | no |
| client\_id | Client identifier used in OAuth requests (`client_id`). Unique within the realm. | `string` | n/a | yes |
| client\_secret | Secret for a CONFIDENTIAL client. Null lets Keycloak generate one, which is exposed by the `client_secret` output. | `string` | `null` | no |
| description | Description of the client. | `string` | `null` | no |
| direct\_access\_grants\_enabled | Enable the resource owner password grant. Deprecated by OAuth 2.1; leave off unless a legacy client needs it. | `bool` | `false` | no |
| full\_scope\_allowed | Put every role of the user into the client's tokens. False limits tokens to roles mapped through client scopes (least privilege). | `bool` | `false` | no |
| login\_theme | Login theme for this client. Null uses the realm theme. | `string` | `null` | no |
| name | Display name in the Keycloak console. Defaults to client\_id. | `string` | `null` | no |
| pkce\_enabled | Require PKCE (S256) on the authorization code flow. Recommended for every client type by OAuth 2.1. | `bool` | `true` | no |
| realm\_id | Realm name (the `id` of a `keycloak_realm` resource). | `string` | n/a | yes |
| root\_url | Root URL of the application, prepended to relative redirect URIs. | `string` | `null` | no |
| service\_accounts\_enabled | Enable the client credentials grant (machine-to-machine). CONFIDENTIAL clients only. | `bool` | `false` | no |
| standard\_flow\_enabled | Enable the authorization code flow. Ignored for BEARER-ONLY clients. | `bool` | `true` | no |
| valid\_redirect\_uris | Allowed redirect URIs. HTTPS only, except `http://localhost` and `http://127.0.0.1` for local development. A trailing `/*` is allowed; a bare `*` is not. | `list(string)` | `[]` | no |
| web\_origins | Allowed CORS origins. `+` (the default) allows the origins of `valid_redirect_uris` and nothing else. | `list(string)` | ```[ "+" ]``` | no |

## Outputs

| Name | Description |
|------|-------------|
| client\_id | Client identifier used in OAuth requests. |
| client\_secret | Secret of a CONFIDENTIAL client; null for other access types. |
| id | Internal Keycloak ID (UUID) of the client. Other resources (roles, scopes, mappers) reference this. |
| service\_account\_user\_id | ID of the service account user when service accounts are enabled, for assigning roles to it. |
